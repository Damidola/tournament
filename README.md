# Турнир ♞

Шахматный турнир с телефона и ПК. Статический сайт на [GitHub Pages](https://damidola.github.io/tournament/) без сервера и обязательной регистрации.

## Что работает

- Несколько турниров: подготовка, игра и завершённые результаты.
- Детский / клубный режим без рейтингов и расширенный режим с рейтингом для стартового посева и статистикой игрока.
- Круговой турнир: все пары по одному разу, сбалансированные цвета, правильное число туров для нечётного состава. Отдых не даёт очков.
- Клубная швейцарка: близкие очки, предпочтения цвета, подбор без повторов, свободный тур с 1 очком. Это собственный клубный алгоритм, **не FIDE Dutch**. До 64 участников. Если допустимых пар нет, система останавливается, а не добавляет скрытые повторы; можно завершить турнир досрочно после закрытия текущего тура.
- Результаты 1–0, ½–½, 0–1; отдельные результаты неявки +−, −+, −−.
- Бухгольц, Бухгольц Cut-1, Зоннеборн — Бергер и победы за доской; порядок можно выбрать до старта. В круговом турнире доступны только ЗБ и победы.
- Карточка игрока с каждым слагаемым коэффициентов и графиком накопленных очков в расширенном режиме.
- Таблица после выбранного тура, CSV, печать таблицы / сохранение в PDF средствами браузера, копирование пар.
- Возврат к выбранному туру: его результаты сохраняются, зависимые следующие туры отменяются. Полное предыдущее состояние можно вернуть из истории.
- JSON-копии всех турниров или одного турнира, перенос между устройствами, проверка данных перед импортом. Копии импортируются отдельно, текущие записи не перезаписываются.
- Работа офлайн после первого успешного открытия и загрузки service worker. Для мобильного использования сайт можно добавить на главный экран через меню браузера.

## Правила мест и коэффициентов

Очки всегда первые. При равных очках сравниваются выбранные коэффициенты в заданном порядке. Рейтинг не используется для разрешения равенства. При полном равенстве игроки разделяют место; номер посева упорядочивает только отображение.

БХ = сумма очков соперников. БХ−1 исключает один наименьший вклад; если игрок проиграл из-за неявки, сначала исключается наименьший вклад его неявок. ЗБ = сумма очков соперников, умноженных на результат против каждого. Победы — только сыгранные партии, без свободных туров и неявок.

Обработка свободных туров и неявок основана на [правилах коэффициентов FIDE с 1 марта 2026](https://handbook.fide.com/chapter/TieBreakRegulations032026):

- В швейцарке (§16.4) вклад условного соперника для свободного тура ограничен минимумом собственных очков игрока и половины запланированного числа туров. Для неявки — минимумом собственных очков и очков назначенного соперника.
- В круговом турнире (§15) неявки учитываются как назначенные встречи с очками реального соперника; отдых исключён.
- Незавершённые партии не добавляют очков или коэффициентов. Текущие коэффициенты пересчитываются при каждом результате и могут измениться до конца турнира.

Запрошенные пропуски, снятие участников, командные турниры, нокаут, анализ шахматных ходов и официальный пересчёт Elo не реализованы. Аналитика — статистика результатов, а не шахматный движок. Для официального рейтингового соревнования нужен проверенный механизм жеребьёвки и регламент судьи.

## Сохранение

Каждая операция записывается до подтверждения в интерфейсе. Две чередующиеся записи `localStorage` содержат контрольную сумму. При повреждении последней записи используется предыдущая. При ошибке записи интерфейс сообщает, что изменение **не сохранено**, а состояние приложения не обновляется.

История содержит полные снимки перед последними 24 изменениями каждого турнира; восстановление тоже создаёт снимок. Закрытые туры и состав после старта защищены от редактирования. Устаревшая вкладка не может перезаписать более свежую версию. JSON-импорт проверяет игроков, результаты, пары, повторы, завершение туров и историю.

Данные локальны: синхронизации между устройствами и публичной общей таблицы пока нет. Регулярно скачивайте JSON, особенно перед очисткой браузера. Файл резервной копии содержит имена участников. Записи первой версии оставлены в старом ключе и доступны для отдельного скачивания на странице копий.

## Разработка и проверки

Нужен Node.js 24 для автоматических проверок. У production-сайта нет npm-зависимостей.

```sh
npm test
python3 -m http.server 4173
```

Не открывайте HTML через `file://`: браузерные ES-модули и service worker требуют HTTP(S). Откройте `http://localhost:4173`.

`tests/engine.test.js` проверяет заранее рассчитанные итоги, коэффициенты, неявки, свободные туры, равные места, круговые расписания, разнообразные швейцарские турниры и возврат. `tests/storage.test.js` проверяет повреждение и восстановление, ошибку записи и конфликт вкладок.

Необязательная проверка браузера требует Playwright и Chromium / Google Chrome:

```sh
npm install --no-save --ignore-scripts playwright@1.56.1
CHROME_BIN=/usr/bin/google-chrome node tests/ui.cjs
```

GitHub Actions выполняет проверки расчётов и сценарии телефона / ПК перед публикацией из `main`, сохраняет скриншоты как `interface-previews` и публикует только статические файлы. В Settings → Pages источник должен быть **GitHub Actions**.
